Native CoreAudio soundРодной звук через CoreAudio原生 CoreAudio 声音

A virtio-snd device with a CoreAudio backend written for steamac — no PipeWire on the Mac, no drivers to install.Устройство virtio-snd с бэкендом CoreAudio, написанным для steamac: без PipeWire на Mac и без драйверов.为 steamac 编写的 CoreAudio 后端 virtio-snd 设备——Mac 上无需 PipeWire，无需安装驱动。

  • The guest stream (8–48 kHz, mono or stereo, integer or float) is copied into a lock-free ring; CoreAudio's real-time callback only reads from it.Поток гостя (8–48 кГц, моно или стерео, целые или float) копируется в lock-free кольцевой буфер; real-time колбэк CoreAudio только читает из него.客户机音频流（8–48 kHz、单声道或立体声、整型或浮点）拷贝到无锁环形缓冲；CoreAudio 实时回调只从中读取。
  • Playback is paced by the output device's clock, so the guest never runs ahead of real time; the reported latency includes CoreAudio's own, keeping audio and video in sync.Воспроизведение идёт по часам устройства вывода — гость не убегает вперёд реального времени; в задержку включена задержка самого CoreAudio, звук не расходится с картинкой.按输出设备时钟播放，客户机不会跑到真实时间前面；上报延迟包含 CoreAudio 自身延迟，音画保持同步。
  • Output device, volume and buffer (10 / 20 / 60 ms) change on the fly; if a device disappears, sound falls back to the system default. The microphone opens only while SteamOS records.Устройство вывода, громкость и буфер (10 / 20 / 60 мс) меняются на лету; пропало устройство — звук уходит на системное. Микрофон открывается только пока SteamOS записывает.输出设备、音量和缓冲（10 / 20 / 60 毫秒）可实时切换；设备消失则回落到系统默认。仅 SteamOS 录音时才打开麦克风。

04 · Graphics translationТрансляция графики图形转译

DirectX → Vulkan → Metal

Windows games render through a chain of translations, GPU-accelerated end to end.Windows-игры рисуют через цепочку трансляций — с аппаратным ускорением на всём пути.Windows 游戏经多层转译渲染，全程 GPU 加速。

  • DXVK in Proton turns DirectX 9/10/11 into Vulkan, vkd3d-proton does the same for DirectX 12. Mesa's Venus driver in the VM serializes the Vulkan calls to the host over virtio-gpu, sharing memory as 16K-aligned blobs.DXVK в Proton превращает DirectX 9/10/11 в Vulkan, vkd3d-proton — DirectX 12. Драйвер Venus из Mesa внутри ВМ сериализует вызовы Vulkan и передаёт их хосту через virtio-gpu; память общая — blob-ресурсы с выравниванием 16K.Proton 中的 DXVK 把 DirectX 9/10/11 转成 Vulkan，vkd3d-proton 对 DirectX 12 同理。虚拟机内 Mesa 的 Venus 驱动经 virtio-gpu 把 Vulkan 调用序列化发往宿主，内存以 16K 对齐 blob 共享。
  • On the Mac, virglrenderer replays them on a Vulkan driver that runs on Metal: KosmicKrisp (Mesa, Metal 4, macOS 26+) or MoltenVK (Metal 3, macOS 15+). SteamOS sees “Virtio-GPU Venus (Apple M4 Max)” with Vulkan 1.4.На Mac virglrenderer исполняет их на Vulkan-драйвере поверх Metal: KosmicKrisp (Mesa, Metal 4, macOS 26+) или MoltenVK (Metal 3, macOS 15+). SteamOS видит «Virtio-GPU Venus (Apple M4 Max)» с Vulkan 1.4.在 Mac 上，virglrenderer 在基于 Metal 的 Vulkan 驱动上重放它们：KosmicKrisp（Mesa、Metal 4、macOS 26+）或 MoltenVK（Metal 3、macOS 15+）。SteamOS 看到的是带 Vulkan 1.4 的“Virtio-GPU Venus (Apple M4 Max)”.
  • Patched MoltenVK adds what DXVK and vkd3d-proton need: geometry shaders, transform feedback, depth clip, null descriptors, million-entry descriptor heaps, texel buffers at any offset. Metal caches compiled shaders — a new effect stutters once, then never again.Пропатченный MoltenVK даёт то, что нужно DXVK и vkd3d-proton: геометрические шейдеры, transform feedback, depth clip, null-дескрипторы, кучи дескрипторов на миллион записей, texel-буферы с любым смещением. Metal кеширует шейдеры — новый эффект подтормаживает один раз, потом никогда.打过补丁的 MoltenVK 补齐了 DXVK 与 vkd3d-proton 所需：几何着色器、transform feedback、depth clip、null 描述符、百万级描述符堆、任意偏移 texel 缓冲。Metal 缓存编译好的着色器——新特效只卡一次，之后不再卡。

  • x86 code expects strong memory ordering (TSO). Real SteamOS, tiny VMНастоящий SteamOS, маленькая ВМ真正的 SteamOS，微型虚拟机

Valve's own ARM64 SteamOS image, booted by libkrun on Hypervisor.framework — no QEMU, no CPU emulation for the OS.Собственный ARM64-образ SteamOS от Valve, загруженный libkrun на Hypervisor.framework — без QEMU и без эмуляции процессора для системы.Valve 自家的 ARM64 SteamOS 映像，由 libkrun 在 Hypervisor.framework 上启动——无 QEMU，系统本身无需 CPU 模拟。

  • The image comes from Valve as a signed RAUC bundle; signature and sha256 are verified. The SteamOS root filesystem is never modified — VM bits live in the initramfs and a separate read-only layer.Образ скачивается с серверов Valve подписанным RAUC-бандлом; подпись и sha256 проверяются. Корневая ФС SteamOS не изменяется — всё для ВМ живёт в initramfs и отдельном read-only слое.映像来自 Valve 的签名 RAUC 包；校验签名与 sha256。SteamOS 根文件系统从不动——虚拟机所需全部在 initramfs 与独立只读层中。
  • So official updates just work: RAUC installs into the other A/B slot and rolls back the standard way, with the initramfs acting as the bootloader.Поэтому официальные обновления просто работают: RAUC ставит их в другой слот A/B и откатывает штатно, а initramfs играет роль загрузчика.因此官方更新开箱即用：RAUC 安装到另一个 A/B 槽并按标准方式回滚，initramfs 充当引导器。
  • vCPU and GPU threads run at user-interactive QoS; networking goes through gvproxy. SSH into SteamOS is one switch in Settings, off by default, with a generated password per disk.Потоки vCPU и GPU работают с QoS user-interactive; сеть — через gvproxy. SSH в SteamOS — один переключатель в настройках, по умолчанию выключен, пароль генерируется для каждого диска.vCPU 与 GPU 线程以 user-interactive QoS 运行；网络经 gvproxy。SSH 进 SteamOS 是设置中的一个开关，默认关闭，每个磁盘生成独立密码。
  • Closing the window can suspend instead of shutting down: the vCPUs and the guest's audio stop in place and the game waits in memory. Resume from the Dock or the menu bar and you are exactly where you left off. SteamOS's own Sleep pauses the VM the same way.Закрытие окна может не выключать, а приостанавливать: vCPU и звук гостя останавливаются на месте, игра ждёт в памяти. Продолжить — из Dock или строки меню, ровно с того же места. Сон SteamOS ставит ВМ на паузу так же.关闭窗口可选择暂停而非关机：vCPU 与客户机音频原地停止，游戏在内存中等待。从程序坞或菜单栏继续，精确回到离开时的状态。SteamOS 自身的睡眠也以同样方式暂停虚拟机。

Proton переводит DirectX в Vulkan внутри SteamOS; Venus выносит вызовы Vulkan из ВМ; на Mac Vulkan-драйвер превращает их в Metal.
